# Ssokly

**캡처를 보관하고, 쓸 수 있는 텍스트로.** 학교 공문·업무 화면을 캡처해 원본과 함께 보관하고, 텍스트를 대조·수정해 복사하거나 필요한 내용만 AI로 정리하는 Windows 데스크톱 앱입니다.

## 최근 보완 · 2026-09-28

**더보기 → 캡처 저장 폴더 설정**에서 현재 위치를 확인하거나 폴더를 열고 변경할 수 있습니다. 신규 사용자는 첫 실행에 실제 Windows 바탕화면의 **`ssokly`** 폴더를 만듭니다(OneDrive로 옮겨진 바탕화면 포함). 기존 자료가 있으면 원래 위치를 유지합니다. 변경할 때는 다른 Ssokly 창을 닫고 **빈 폴더**를 선택하세요. 이미지·OCR·캡처 휴지통 정보를 검증해 복사한 뒤 앱을 종료하며, 다시 실행하면 새 위치를 사용합니다. 이전 원본은 자동 삭제하지 않습니다.

캡처 모서리와 문서를 조합한 새 앱 아이콘, 청록색 주요 버튼, 밝은 작업 배경을 적용했습니다. 보관함 검색 결과는 선택 색상과 교차 행 배경으로 구분합니다. **자료 정리 · 라벨 / 쪽** 메뉴에서 라벨 이름 변경과 쪽 합치기·분리를 실행합니다. 좁은 화면에서는 관리 버튼이 목록을 밀어내지 않도록 메뉴로 묶었습니다.

개발용 검증은 `python tools/verify_capture_desk.py --all`(전체 오프라인 검사), `python tools/verify_reopen_flow.py`(임시 자료로 종료·재열기 검사)를 사용합니다. `python tools/preview_capture_desk.py`는 별도 합성 자료 미리보기입니다. `python tools/evaluate_capture_quality.py`는 합성 표·안내 이미지 두 장만 만들며, `--live`를 명시하면 기존 API 설정으로 유료 OCR 2회와 AI 정리 3회를 실행합니다. 평가 결과는 `.local-results`에 저장하며 자동 검사는 실제 공문의 정확도를 보장하지 않습니다.

**더보기 → 캡처 관리 · 전체 이미지**를 열고 **검색 → 캡처 선택 → 열기·편집·이동·삭제** 순서로 사용합니다. 썸네일을 선택하면 큰 원본 미리보기가 나오고 더블클릭/열기로 해당 쪽으로 이동합니다. 이름·문서 제목·본문/OCR·라벨·메모를 한 검색칸으로 찾습니다. 라벨 필터와 정렬은 필요할 때 `필터·정렬`을 펼칩니다. 접어도 조건이 유지되면 `적용 중`을 표시하며 `전체 보기`로 초기화합니다. 처음 150장부터 표시하고, 나머지가 있을 때만 `더 보기`가 나옵니다.

**여러 장 선택**을 켜면 Ctrl 키 없이 캡처를 클릭해 선택·해제할 수 있습니다. `표시된 항목 전체 선택`도 이때 나타납니다. 선택한 항목을 **이동**하거나 **삭제**하면 되며, 삭제는 복원 가능한 휴지통 이동입니다. 여러 장 선택을 끄면 한 장만 선택한 상태로 돌아갑니다. 이동은 화면 목록 순서대로 선택한 기존 문서 뒤에 붙이며 원본·OCR·수정본·가림 설정을 유지합니다. 대상 문서의 라벨·메모를 따르고 기존 AI 결과는 원래 문서에 남습니다. 모든 쪽을 옮긴 원래 문서는 휴지통에 보관되며 문서 복원만으로 이동을 되돌리지는 않습니다. 일괄 삭제로 문서가 비면 문서도 휴지통으로 이동하고, 그 문서를 복원하면 마지막 일괄 삭제에 포함된 쪽들이 함께 돌아옵니다. 이전에 따로 삭제한 쪽은 유지합니다.

한 장을 선택한 뒤 **편집 → 이름 변경 / 라벨·메모**를 사용합니다. 이름은 선택한 캡처의 표시 이름만 바꾸며 원본 파일명을 변경하지 않습니다. 라벨·메모는 그 캡처가 속한 문서 전체에 적용합니다. 라벨은 쉼표로 구분해 추가·수정·제거합니다. 다른 문서와 같은 원본을 공유하더라도 캡처 표시 이름은 문서별로 유지합니다. 기존 읽기 전용 캡처는 `열기 → 새 문서로 가져오기` 후 정리하세요. 관리 기능은 로컬 처리이며 AI를 호출하지 않습니다.

원본 이미지 또는 페이지 선택칸을 우클릭하면 **이 페이지 삭제 · 휴지통으로**를 사용할 수 있습니다. 원본 영역의 **이 페이지 삭제** 버튼도 같은 기능입니다. 다른 페이지는 유지되며 **삭제한 페이지 · 복원**에서 문서명과 페이지를 골라 복원합니다. 마지막 페이지를 삭제하면 문서와 라벨·메모도 함께 휴지통으로 이동합니다. 이전 버전에서 삭제된 페이지만 남은 문서도 시작 시 휴지통으로 정리하며, 처음부터 페이지가 없는 새 문서는 유지합니다. 삭제된 페이지는 전체 복사·본문 검색·새 AI 입력에서 제외되지만 영구 삭제 전에는 원본 이미지·OCR·수정본과 기존 AI 결과를 보존합니다. 기존 읽기 전용 기록은 새 문서로 가져온 뒤 페이지를 편집합니다.

문서 전체는 보관함의 **선택 문서 삭제** 또는 목록 우클릭으로 휴지통에 옮깁니다. **문서 휴지통 보기 → 문서 선택 → 선택 문서 복원**으로 복원합니다. 마지막 페이지 삭제로 자동 이동한 문서를 복원하면 마지막으로 삭제한 쪽도 복원됩니다. 해당 페이지를 직접 복원해도 문서가 돌아옵니다. 그 전에 개별 삭제한 다른 쪽은 휴지통에 유지합니다. 문서를 직접 삭제했다면 문서를 먼저 복원하세요.

문서 휴지통에서 **선택 휴지통 문서 영구 삭제** 또는 우클릭 메뉴를 사용합니다. 페이지 휴지통에는 **선택 페이지 영구 삭제**가 있습니다. **휴지통 비우기**는 현재 검색·라벨 필터와 관계없이 휴지통 문서와 개별 삭제 페이지 전체를 대상으로 합니다. 확인창에 표시된 대상만 삭제하며 확인 이후 새로 삭제한 항목은 유지합니다. 영구 삭제는 복원할 수 없고 문서의 라벨·메모·결과도 제거합니다. 다른 문서가 공유하는 이미지와 외부 원본 파일은 보존합니다. 이전 백업·전송 제한 설정은 유지하므로 저장장치 전체의 보안 삭제 기능은 아닙니다. 사용 중인 이미지 파일 정리에 실패하면 상태 표시줄에 남은 정리를 알립니다.

라벨 입력칸은 계속 직접 수정할 수 있고, **라벨 선택**에서 기존 라벨을 클릭해 추가·해제할 수 있습니다. **라벨 관리 · 이름 변경**은 휴지통을 포함해 같은 라벨이 붙은 모든 문서에 반영합니다. 이미 있는 이름으로 바꾸면 중복 라벨을 합칩니다. 자료 저장소는 업그레이드 전 자동 백업 후 페이지 휴지통 필드를 추가합니다.

**원본 이미지와 텍스트·표·업무 실행 탭을 함께 표시**합니다. 보관함을 접은 뒤 실제 작업 폭이 충분하면 좌우로 놓고, 좁은 창에서는 위아래로 각각 절반 정도를 배정합니다. 원본이 얕은 띠처럼 줄어들지 않도록 최소 높이를 확보합니다. 제목 옆 **라벨·메모**를 누르면 분류 입력칸이 펼쳐지며 다시 누르면 접힙니다. 입력값은 유지됩니다. 분할선을 드래그해 비율을 조절하고 **화면 비율 초기화**로 기본 비율로 돌아갑니다. 좁은 창의 이미지 확대·축소·100%·맞춤은 이미지 우클릭 메뉴에서 사용합니다.

**쪽 합치기 / 쪽 분리**는 보관함의 `자료 정리 · 라벨 / 쪽` 메뉴 또는 `더보기`에서 엽니다. 합치기는 현재 문서와 공통 라벨이 하나 이상 있거나 비어 있지 않은 메모가 같은 문서를 후보로 보여 줍니다. 선택한 문서의 보이는 쪽만 목록 순서대로 현재 문서 뒤에 옮깁니다. 현재 문서의 제목·라벨·메모는 유지하고, 원래 문서는 휴지통으로 옮겨 메모·과거 AI 결과·삭제한 쪽을 보존합니다. 같은 캡처가 중복되면 합치기를 중단합니다. 문서 휴지통 복원은 쪽 이동 자체를 되돌리지 않으며, 필요한 쪽은 분리 기능으로 다시 나눌 수 있습니다.

분리 창에서는 Ctrl/Shift로 쪽을 골라 새 문서 제목을 입력합니다. 기존 문서에 한 쪽 이상 남겨야 합니다. 새 문서는 라벨·메모를 이어받고, 옮긴 쪽의 원본·최초 OCR·수정본·가림 설정을 유지합니다. 페이지 순서는 원래 순서를 따릅니다. 기존 AI 결과는 원래 문서에 남고 새 원문과 달라지면 이전 원문 기반으로 표시합니다. 합치기·분리는 로컬 처리이며 외부 AI를 호출하지 않습니다.

### 이전 보완 · 2026-09-17

자료 라이브러리에 문서별 라벨·메모와 검색·라벨 필터를 추가했습니다. 검색 입력칸의 범위를 표시하고 버튼·Enter·입력값 변경으로 조회할 수 있게 했으며, 좁은 목록에서는 날짜·쪽 수와 분류 상태를 나누어 보여 줍니다.

Windows의 AppData 경로 전환으로 정상 캡처의 등록·조회·복구가 막히던 문제를 보완했습니다. 같은 실제 파일임이 확인되는 경로만 허용하며 외부 파일·링크 검사는 유지합니다. 원본이 없거나 경로에 문제가 있는 기록은 전체 보관함을 막지 않고 `복구 필요`로 표시합니다. 해당 페이지의 저장된 텍스트는 읽기·복사할 수 있고 정상 페이지는 계속 편집합니다. 자세한 확인 범위와 한계는 [최신 검증 기록](VALIDATION.md)에 있습니다.

## 설치와 실행

Windows와 tkinter가 포함된 Python이 필요합니다. 기존 검증 환경은 Python 3.12.10이며, Python 3.9.7 환경의 시작·캡처 파일 조회·표 글꼴 호환 오류도 보완했습니다. 환경별 검증 범위는 [VALIDATION.md](VALIDATION.md)를 참고하세요. 저장소 루트에서 PowerShell로 실행합니다.

```powershell
python -m venv .venv
.\.venv\Scripts\python.exe -m pip install -r requirements.txt
.\.venv\Scripts\python.exe main.py
```

콘솔 없이 실행하려면 `.venv\Scripts\pythonw.exe main.py`를 사용합니다. `main.py`는 새 캡처 중심 화면을 엽니다.

현재 앱은 `ai-server.json`의 테스트 서버를 통해 OCR·AI 정리를 사용합니다. **사용자 로그인이나 로컬 OpenAI 키가 필요하지 않습니다.** 선택한 전송 사본이 Vercel 중계 서버를 거쳐 OpenAI로 전달되고, 키는 서버 환경변수에만 보관됩니다. 서버 모드에서는 로컬 `.env`의 키를 읽거나 전송하지 않으며 실패해도 직접 호출로 전환하지 않습니다. 보관·편집·검색·복사·로컬 문서 읽기는 계속 PC에서 처리합니다.

개발자가 직접 호출을 시험할 때만 `SSOKLY_API_URL`을 빈 문자열로 설정하거나 `ai-server.json`의 URL을 비운 뒤 로컬 `.env`에 키를 설정합니다. 기존 개발 키는 보존하되 **작업 폴더 전체를 제출하지 마세요.** `python tools/build_submission.py --url https://ssokly-ai-relay.vercel.app`로 생성한 `dist/Ssokly-submission.zip`은 키·가상환경·사용자 자료를 제외한 소스 제출본입니다. EXE는 별도 패키징이 필요하며 `ai-server.json`을 EXE 옆에 둡니다. 자세한 운영 방법은 [백엔드 안내](backend/README.md)를 참고하세요.

서버 모드는 완성된 결과를 한 번에 표시합니다. 전송 사본은 4MB, AI 텍스트 입력은 10만 자까지이며 큰 이미지는 영역을 나눠 캡처하세요. 테스트 서버를 중지하면 AI 기능만 사용할 수 없고 로컬 자료는 유지됩니다. OCR과 AI 정리는 `gpt-5-nano`로 지정합니다. 예전 카드 분석·이미지 생성은 이번 중계 대상이 아닙니다.

## 기본 흐름

**새 캡처/파일 열기 → 자료 라이브러리 → 텍스트 인식 → 대조·수정 → 업무 실행(요약·할 일·안내문)**

1. 캡처 전에 `보관만 / 자동 인식 / 가리고 읽기`를 고릅니다. 처음에는 `보관만`입니다.
2. `새 캡처`로 문서를 시작합니다. 같은 문서의 다음 장은 `+ 페이지`로 추가합니다. 영역 선택 취소는 Esc입니다.
3. 가운데 원본과 오른쪽 텍스트를 대조하고 바로 수정합니다. 편집창은 선택한 페이지 하나이며 검수 완료를 강제하지 않습니다.
4. `선택 복사 / 페이지 복사 / 전체 복사`로 활용합니다. 전체 복사와 AI 입력은 현재 페이지 순서의 수정본을 사용합니다.
5. 제목 옆 `라벨·메모`를 눌러 입력칸을 펼치면 자동 저장하며 분류할 수 있습니다. 예를 들어 `공문, 행사`처럼 분류하고, 메모에는 후속 확인 사항을 적을 수 있습니다. 한 자료에 라벨은 최대 8개(각 24자), 메모는 2000자까지 저장합니다. 보관함에서 라벨로 좁히거나 제목·본문·인식 원문·라벨·메모를 검색합니다.

### 화면

- **자료 라이브러리:** `자료 검색` 입력칸에 제목·본문·인식 원문·라벨·메모의 단어를 입력하면 목록이 갱신됩니다. `검색` 버튼이나 Enter로 즉시 조회할 수도 있습니다. 검색어를 지우면 전체 목록으로 돌아갑니다. 라벨 필터와 날짜·썸네일·페이지 수·분류 상태를 표시하며, 라벨이 없는 자료는 짧은 메모를 미리 보여 줍니다. 기존 업무 연결 여부와 무관하게 찾습니다. 최근 250개부터 표시하며 `더 보기`로 이어서 불러옵니다. 기존 읽기 전용 기록은 `새 문서로 가져오기` 후 라벨·메모를 편집합니다.
- **원본:** 페이지 선택, ↑/↓ 순서 변경, 확대·축소·맞춤·100%, 드래그 이동과 스크롤. 선택한 원본만 크게 불러오고 썸네일은 재사용합니다.
- **작업 영역:** `텍스트 / 표 / 업무 실행`. 업무 실행에서 기존 AI 정리 기능(요약·일정/할 일·안내문)을 사용합니다. 표는 같은 영역에서 보고 선택 행/전체 표를 빈 셀을 유지한 TSV로 복사합니다. 표 셀 수정은 텍스트 탭에서 합니다.

창 폭과 화면 배율에 따라 보관함을 접고 원본/편집 영역을 좌우 또는 상하로 배치합니다. 원본과 편집 탭을 하나씩 숨기는 전환은 사용하지 않습니다. 최소 창 크기는 720×680입니다. `보관함` 버튼으로 목록을 다시 열며, 공간이 부족하면 목록을 넓게 표시하고 문서를 선택하면 작업 영역으로 돌아갑니다. 분할선 위치를 보정해 원본·편집 영역의 공간을 확보합니다. 업무 카드·필드별 확인·담당 역할·할 일 관리·도식화는 새 기본 화면에 없습니다.

### 저장과 복구

제목·라벨·메모·페이지 텍스트·AI 결과를 편집하면 약 700ms 뒤 자동 저장하며 하단에 상태를 표시합니다. `Ctrl+S`로 즉시 저장합니다. 이동·종료 전에 저장하고, 실패하면 입력을 유지하며 이동을 막습니다.

다른 창의 변경과 충돌했다면 필요한 내용을 먼저 `페이지 복사`·`결과 복사`로 보관한 뒤 `더보기 → 저장된 최신값 다시 열기…`를 사용합니다. 확인한 경우에만 미저장 입력을 버립니다. 저장된 내용을 읽지 못하면 입력은 유지합니다.

`다시 읽기`는 인식 원문을 갱신하지만 직접 수정한 텍스트(빈칸으로 지운 값 포함)는 덮어쓰지 않습니다. 새 화면에서 처음 인식한 내용은 별도로 보존하고, `더보기 → 원래 인식 내용 보기`에서 최근 인식본과 함께 열람·복사합니다. 기존 자료는 남아 있는 인식본부터 보존하며 과거에 덮인 OCR까지 복구하지는 않습니다. 새 인식 내용을 편집본에 쓰려면 필요한 부분을 직접 복사해 반영하세요.

이미지는 OCR보다 먼저 로컬에 저장합니다. OCR 실패·취소에도 원본과 마지막 성공 인식본·수정본을 유지합니다. PNG 저장 후 DB 기록만 실패한 경우 정상 이미지를 보관함 조회/재시작 때 복구합니다. 이미지 자체를 쓸 수 없는 디스크 오류·손상이나 저장 전 정전까지 복구를 보장하지는 않습니다.

`복구 필요` 페이지는 원본 상태를 확인할 때까지 읽기 전용이며 재OCR·원본 전송을 실행하지 않습니다. 저장된 텍스트를 복사해 활용할 수 있고, 같은 문서의 정상 페이지는 계속 작업할 수 있습니다. DB 전체를 읽지 못한 경우에는 빈 보관함으로 성공 처리하지 않고 오류를 안내합니다.

`선택 문서 삭제 / 복원`과 `더보기 → 현재 문서 휴지통 / 복원`은 문서의 보관 상태만 바꿉니다. 휴지통 항목은 읽기 전용이며 복원 후 편집합니다. 기존 업무 기록은 삭제하지 않고 기존 캡처 휴지통 항목도 복원하거나 영구 삭제할 수 있습니다. 클라우드 동기화는 제공하지 않습니다.

### 날짜와 표

유효하게 해석한 날짜는 청록색, 불확실한 글자·판독불가·잘못된 날짜·날짜/요일 충돌·부분 해석된 시간은 해당 부분만 빨간 밑줄로 표시합니다. 색상은 정확도 보증이 아니며 복사·AI 정리를 막지 않습니다.

표 보기는 추출 텍스트의 행·열·빈 셀·병합 표시와 긴 셀 내용을 확인하는 기능이며 원본 지면을 재현하는 뷰어가 아닙니다. HWPX 병합 셀은 `↳`, 셀 안 줄바꿈·탭은 ` / `·` | `로 구분합니다. 잘못된 좌표·겹친 셀은 임의로 덮어쓰지 않고 오류를 안내합니다. 복잡한 캡처 표는 원본과 대조하세요.

## OCR과 AI 정리

`자동 인식`은 처음 설정할 때 **새 캡처의 OpenAI 전송과 비용 발생**에 동의해야 켜집니다. `보관만`은 자동 전송하지 않으며 나중에 `다시 읽기`에서 전송을 선택합니다. `가리고 읽기`는 가린 사본을 선택해야 실행됩니다. 자동 인식 동의로 이전 가림을 해제하지 않습니다. 캡처 뒤 카드 분석·추가 AI 재검토는 자동 실행하지 않습니다.

`업무 실행` 탭에서 필요한 AI 정리 작업만 요청합니다.

- **요약:** 목적·핵심 내용·주요 기한.
- **일정·할 일 정리:** 학교 업무와 행사일·보고일·외부 기관 일정을 구분한 복사 가능한 텍스트. 별도 할 일 DB에 등록하지 않습니다.
- **안내문:** 교직원 메신저·학부모 메신저·가정통신문 초안.

기본 입력은 **문서 전체의 현재 수정본**입니다. 텍스트 탭에서 일부를 선택하고 `선택한 텍스트만 정리`를 켜면 그 부분만 사용합니다. 전송 사본을 확인하고 카드 추출 없이 한 번의 생성 요청으로 처리합니다. 원문에 없는 날짜·담당·의무를 만들지 않고 조건과 날짜 표현을 유지하도록 지시하지만 AI 판단은 원본 검수가 필요합니다.

결과는 원문과 분리하여 편집·복사·자동 저장합니다. 최근 결과를 보여주고 `이전 결과`에서 과거 결과를 엽니다. 생성 중 편집하거나 다른 문서로 이동하면 늦은 결과는 이력에만 남고 작업 중인 입력을 덮지 않습니다. 원문이 바뀐 결과에는 이전 원문 기반임을 표시합니다. 마지막으로 열어 편집한 결과도 재열기 때 복원합니다. 중단·실패한 재생성으로 기존 결과를 바꾸지 않습니다. `처리 취소`는 결과 적용을 막지만 이미 전송된 요청의 비용까지 취소하지는 않습니다.

## 파일과 기존 기록

| 입력 | 처리 |
| --- | --- |
| PNG/JPG/JPEG/BMP/WEBP | 원본 보관, 읽기 실행 시 별도 전송 확인 |
| TXT/MD/CSV/TSV/JSON/XML/HTML | UTF-8·CP949·BOM 있는 UTF-16 로컬 읽기. 마크업은 코드 그대로 표시 |
| PDF | 각 쪽의 원본 이미지와 내장 텍스트를 로컬 저장. 스캔 쪽은 선택 후 다시 읽기로 OCR |
| HWPX | 본문·탭 기반 표를 한 항목으로 읽고, 참조된 삽입 이미지는 별도 OCR 대상 항목으로 보관 |
| DOCX / RTF / ODT | 본문 텍스트 로컬 읽기. DOCX·ODT 표는 탭으로 구분 |
| PPTX / ODP | 슬라이드별 텍스트·표 로컬 읽기 |
| XLSX / ODS | 시트별 텍스트·표 로컬 읽기. XLSX는 보이는 시트만 읽으며 빈 셀·날짜·백분율 유지 |
| 구형 HWP/DOC/PPT/XLS | 직접 읽기 미지원, 지원 목록에서 제외. HWPX/DOCX/PPTX/XLSX 또는 PDF로 변환 |

PDF·HWPX·Office의 파일 열기 자체에는 API를 호출하지 않습니다. PDF 스캔 쪽이나 HWPX 삽입 이미지는 해당 항목을 선택하고 `다시 읽기`로 전송 사본을 확인한 뒤 OCR합니다. PDF 내장 텍스트는 표의 칸 배치를 재구성하지 않으므로 원본과 대조하거나 쪽 이미지 OCR을 사용하세요. XLSX 수식은 직접 계산하지 않으며 저장된 계산값이 없으면 `[계산 결과 없음: 수식]`으로 표시합니다.

파일은 최대 50MB, 문서는 최대 100개 쪽/항목을 가져옵니다. PDF 이미지의 긴 변은 최대 2400픽셀입니다. HWPX 본문 항목은 인쇄 페이지 구분이 아닙니다. Office는 본문·셀 읽기이며 원본 페이지 디자인, 도형·차트·그림의 OCR, DOCX 머리말·꼬리말·변경 추적·텍스트 상자까지 보장하지 않습니다. 원본 배치나 그림이 중요하면 PDF로 저장해 여세요. HWPX의 지원하지 않는 벡터 이미지도 PDF 변환이 필요합니다.

`더보기 → 원본 문서 파일 열기`로 원래 문서를 기본 프로그램에서 열 수 있습니다. 원본 문서 파일 전체를 앱 폴더에 복제하지는 않습니다. 원본을 옮겨도 저장한 추출 텍스트와 PDF 쪽 이미지·HWPX 삽입 이미지는 유지되지만, 외부 원본 열기와 텍스트 문서 다시 읽기는 원래 파일이 필요합니다. 앱 휴지통은 외부 원본 파일을 지우지 않습니다.

개발 검사는 `python -m pip install -r requirements-dev.txt` 후 `python tools/verify_capture_desk.py --all`로 실행합니다. `python tools/evaluate_file_reading.py`는 합성 PDF/HWPX 로컬 검사를 수행합니다. `--live`를 붙이면 합성 스캔 이미지 2장에 실제 유료 OCR을 요청합니다. EXE 빌드에서는 PDFium 라이브러리 포함과 패키징 후 파일 열기를 별도로 확인해야 합니다.

과거 업무는 보관함에서 읽기 전용으로 엽니다. `새 문서로 가져오기`는 기존 통합 원문을 한 페이지 사본으로 가져오며 임의로 나누지 않습니다. 이미지·카드·교사 수정값·할 일·초안 이력은 삭제하지 않습니다. `더보기 → 기존 기록 보기`에서 과거 카드의 현재값과 초안·할 일을 열람·복사합니다. 새 작업은 카드 저장 경로를 호출하지 않습니다.

## 데이터와 개인정보

캡처 저장 폴더와 앱 데이터 폴더를 구분합니다. 신규 사용자의 캡처 폴더는 Windows 바탕화면의 `ssokly`이며 설정에서 변경할 수 있습니다. **문서·라벨·메모·AI 결과·전송 설정**과 저장 위치 설정은 `%LOCALAPPDATA%\Ssokly`에 보존합니다. 해당 환경 변수가 없으면 사용자 홈의 `.ssokly`를 사용합니다. 실행 파일 위치나 현재 작업 폴더에 자료를 저장하지 않으므로 EXE 실행 위치가 바뀌어도 저장 설정을 재사용합니다.

기존 `%LOCALAPPDATA%\Ssokly\capture_inbox` 자료는 자동으로 이동하지 않습니다. 설정에서 변경하면 등록된 캡처 이미지와 캡처 DB를 복사하며, 과거 백업과 이전 폴더는 남깁니다. 비어 있지 않은 폴더에는 덮어쓰지 않습니다. 복사·검증·설정 저장에 실패하면 기존 설정을 유지합니다(새 폴더에 완료된 복사본이 남을 수 있습니다). 설정된 저장 장치를 찾을 수 없거나 설정 파일이 손상되면 다른 빈 저장소로 바꾸지 않고 시작 오류를 알립니다.

Windows 앱 가상화에서는 AppData의 실제 위치가 실행 환경에 따라 다를 수 있습니다. EXE 배포 시에는 기존 Python 환경의 자료와 새 실행 환경의 자료가 함께 보이는지 추가 확인해야 합니다. **다른 PC로 이전하거나 백업할 때는 앱을 닫고 캡처 폴더와 앱 데이터 폴더를 모두 보관하세요.** 캡처 폴더만 복사하면 문서·라벨·메모는 이전되지 않습니다.

| `work_cards.sqlite3`, `personal_todos.sqlite3` | 과거 카드·초안·할 일. 새 화면에서 생성·갱신하지 않음 |
| `captures`, `analysis_cache.sqlite3`, `workspace_state.sqlite3`, `settings.json` | 기존 자료·캐시·연결·창 설정 보존 |

구조 변경은 가산 방식이며 업그레이드 전 SQLite 백업(`*.before-*.bak`)을 만듭니다. 최신 DB를 매번 백업하지 않습니다. 여러 DB의 작업이 하나의 원자적 트랜잭션은 아니므로 실패한 문서 연결은 개별 캡처/기존 기록으로 남을 수 있습니다. 다른 PC에서 GitHub 코드만 가져와서는 키나 로컬 자료가 복원되지 않습니다. 앱을 닫고 데이터 폴더 전체를 안전하게 백업하세요.

로컬 보관·편집·검색·복사·재열기는 AI를 호출하지 않습니다. OCR·AI 정리에서는 **선택한 입력이 OpenAI로 전송되고 비용이 발생**합니다. 학교의 외부 AI·개인정보 기준을 먼저 확인하세요.

텍스트 가림은 치환 사본, 이미지 가림은 불투명 영역을 실제 픽셀에 합성한 PNG만 전송합니다. 원본은 유지합니다. PDF/Office 원본 가림은 지원하지 않으며 텍스트/페이지 이미지 사본으로 바꿉니다. 준비 실패·취소 시 원본 자동 대체는 없습니다.

이전 가림 정책은 재열기·재OCR·원문 가져오기·AI 정리에 유지합니다. 전송 범위를 넓힐 때는 별도 확인합니다. 이미지/파일의 개인정보를 자동으로 모두 검출하지는 않습니다. 학부모 안내의 내부 업무·일부 개인정보 필터는 **생성 결과용**이며 전송 전 자동 비식별화가 아닙니다. 자동 발송하지 않습니다.

Responses 요청은 `store=False`를 사용하지만 모든 서버 보관의 부재를 보장하지는 않습니다. 계정·기관의 데이터 정책을 확인하세요. 키·실물 공문·학생/학부모 개인정보·업무 DB를 Git에 올리지 마세요.

## 검증과 개발

합성 문서·이미지, 임시 DB, mock API와 Windows Tk로 검증합니다. 실제 OCR/공문 해석 품질·사용자 마우스 조작·다중 모니터/고배율·EXE 패키징은 별도입니다. 최신 시험 수와 초기 실패/보완 이력은 [VALIDATION.md](VALIDATION.md)에 구분합니다.

```powershell
.\.venv\Scripts\python.exe -m unittest discover -s tests -q
.\.venv\Scripts\python.exe tools/verify_capture_desk.py
.\.venv\Scripts\python.exe tools/verify_release.py
.\.venv\Scripts\python.exe tools/verify_v2_release.py
.\.venv\Scripts\python.exe -m pip check
```

`verify_capture_desk.py`는 통신을 차단하고 임시 저장소로 새 화면·전송·복구 계약을 검사합니다. 실패·건너뜀·통신 시도는 실패로 판정하며 유료 옵션이 없습니다. 기존 도구는 과거 기능 호환을 검사합니다. 일부 과거 도구의 `--live`/`--cloud`는 유료 API를 호출하므로 명시적 승인 없이 사용하지 마세요.

- `ui/capture_desk.py`: 독립 주 화면·자동 저장·응답 보호.
- `ui/desk_widgets.py`: 이미지 뷰·인라인 표·썸네일 캐시.
- `services/document_library.py`: 문서/페이지/결과 저장 계층.
- `services/text_actions.py`, `desk_transfer.py`: 카드 없는 AI 정리·전송 보호.
- `services/legacy_reader.py`: 기존 기록 읽기 전용 열람.
- 기존 OCR·파일 읽기·날짜 검수·캡처 저장을 재사용합니다. `ui/app.py`와 카드·할 일·도식화 코드는 호환/회귀용으로 남으며 기본 화면에서는 사용하지 않습니다.
