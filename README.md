# Ssokly

학교 공문을 읽고 교사가 실행할 업무와 일정을 정리하는 Windows 데스크톱 앱입니다.

## 핵심 사용 흐름

화면 캡처 또는 파일 열기 → 전송 사본 선택 → AI 업무 카드 추출 → 필드별 원문 근거 확인·수정 저장 → 내 할 일·새 안내문 생성

OCR과 분석은 모두 `gpt-5-nano`로 자동 지정합니다. 담당 역할·모델 선택 메뉴는 없습니다. 공문에 나온 담당자 전체의 업무를 정리하고 사용자가 필요한 항목만 선택합니다. Windows 로컬 OCR은 비교용 서비스로 남아 있지만 기본 캡처 경로가 아닙니다. Windows AI TextRecognizer는 연동하지 않았습니다.

## 설치와 실행

Windows와 tkinter가 포함된 Python 환경이 필요합니다. 현재 검증 환경은 Python 3.12.10입니다. 다음 명령은 `main.py`와 `requirements.txt`가 있는 저장소 루트에서 PowerShell로 실행합니다.

```powershell
python -m venv .venv
.\.venv\Scripts\python.exe -m pip install -r requirements.txt
```

저장소 루트의 `.env.example`을 참고해 `.env`에 API 키를 설정합니다. 기존 `.env`가 있다면 키를 덮어쓰지 마세요.

```dotenv
OPENAI_API_KEY=your_api_key_here
OPENAI_OCR_DETAIL=high
OPENAI_IMAGE_MODEL=gpt-image-2.5-flare
```

`.env.example`의 `OPENAI_MODEL`, `OPENAI_OCR_MODEL`, `OPENAI_ANALYSIS_MODEL`은 이전 설정과의 호환을 위해 남아 있습니다. 현재 앱의 OCR·분석 모델을 바꾸지 않으며 기본 서비스도 nano를 사용합니다. 개발·비교 도구의 명시적 모델 인자는 별도입니다. 앱의 캡처 OCR은 `high` 상세도를 명시합니다. 이미지 생성 모델은 `OPENAI_IMAGE_MODEL` 설정을 읽습니다.

```powershell
.\.venv\Scripts\python.exe main.py
```

콘솔 없이 실행하려면 `.venv\Scripts\pythonw.exe main.py`를 사용합니다. 현재 노트북의 저장소 이름은 `autoedu`이므로 추가로 `cd Ssokly`를 실행할 필요가 없습니다.

## 원문 읽기와 검수

1. `화면 캡처`로 문서 영역을 드래그하거나 `첨부 파일 열기`를 사용합니다.
2. 캡처 원본은 로컬 보관함에 저장됩니다. 이미지·API 문서는 `AI로 분석` 또는 `가리고 분석`으로 전송 사본을 선택해야 읽습니다. 취소해도 원본은 유지됩니다.
3. 업무 카드에서 필요한 날짜·담당·대상의 `근거`를 확인하고 수정합니다. 원문 전체 검수 완료를 강제하지 않습니다. 원문 탭과 캡처함의 AI OCR 원문·교사 검수본도 계속 사용할 수 있습니다.
4. `표 보기`로 행·열을 확인하고, 행을 선택해 잘린 셀의 전체 내용을 읽을 수 있습니다. 선택한 표는 TSV로 복사할 수 있습니다.

인식된 유효한 날짜는 **청록색**, `⟦불확실:…⟧`·`⟦판독불가⟧`, 존재하지 않는 날짜·명시 연도의 날짜/요일 충돌은 **빨간 밑줄**로 표시합니다. 청록색은 OCR 정확도 보증이 아니며, 빨간 표시가 없다고 검수가 끝난 것은 아닙니다. 색상은 저장된 원문을 변경하지 않습니다.

### 파일별 처리

| 입력 | 처리 방식 |
| --- | --- |
| PNG/JPG/JPEG/BMP/WEBP | 이미지 OCR API |
| TXT/MD/CSV/TSV/JSON/XML/HTML | 로컬 텍스트 읽기 |
| HWPX | 로컬 XML 추출, 다열 표는 탭으로 보존 |
| PDF/DOC/DOCX/RTF/ODT/PPT/PPTX/XLS/XLSX | API 문서 읽기 경로 제공; 실제 호환성은 파일별 확인 필요 |
| 구형 HWP | 직접 읽기 미지원; HWPX/PDF로 변환하거나 캡처 |

HWPX 병합 셀은 `↳`로 이어지는 값을 표시합니다. 단일열 배치용 표는 문단으로, 중첩 표는 셀 안 텍스트로 펼칩니다. 원본 지면을 그대로 재현하는 뷰어는 아닙니다. 캡처 표는 모델에 빈 셀·열 제목·셀 위치 보존을 지시하지만 복잡한 표의 정확성을 보장하지는 않습니다.

캡처함은 검색, 미분류/업무 연결/전체/휴지통 필터, 여러 장 묶기와 현재 업무 추가를 지원합니다. 재OCR은 교사 검수본을 덮어쓰지 않으며 실패해도 직전 성공 원문을 유지합니다. 여러 장 OCR은 장마다 호출하고 최대 20장으로 제한합니다. 목록은 최근 250개를 먼저 표시합니다.

## 업무 결과와 내 할 일

`업무 카드`의 `AI로 업무 추출 / 재분석`으로 카드부터 만듭니다. 필드별 AI 제안·교사 현재값·확인 상태·실제 근거를 따로 보관합니다. 기한을 지워 빈칸으로 저장한 의도도 재분석 후 유지합니다. 대응이 확실하지 않은 새 결과는 기존 업무를 덮지 않는 비교 후보이며, 확인 후 별도 업무로 채택할 수 있습니다.

카드의 `수정 저장` 후 `현재 정보로 새 초안 만들기`에서 다음 양식을 선택합니다. 새 초안은 현재 카드 값으로 로컬에서 만들므로 추가 분석 비용이 없습니다.

`확인` 체크는 해제할 수도 있으며 `확인 상태 저장`으로 반영합니다. 저장 충돌이 나면 `현재값 비교·충돌 해결`에서 저장된 최신값과 내 편집값을 비교해 적용할 필드를 고릅니다. `편집 취소·현재값 사용`은 선택한 카드의 미저장 편집만 버립니다. 미저장 편집이 있으면 재분석·이동·종료·현재 업무 삭제를 먼저 막아 복구할 기회를 줍니다.

- `업무 일정·체크리스트`: 전체 담당자의 업무와 기한, 원문에서 직접 찾은 일정
- `교직원 메신저`: 교직원에게 전달할 안내 초안
- `학부모 메신저`: 학부모 대상 안내 초안
- `가정통신문 초안`: 가정통신문 구성의 안내 초안
- `원문 요약`: 핵심 요약과 확인 사항. 원문은 유지하지만 현재 결과 탭은 요약으로 교체됩니다.

제출·신청 기한, 행사일, 보고일, 교사가 입력한 개인 준비일을 분리합니다. 연도 미기재·상대 기한은 원문 표기와 확인 사유를 보존하고 현재 연도나 시간을 만들지 않습니다. 필수·조건부·안내·추가 제안·판단 유보를 구분하고, 외부 기관 업무·참고 일정은 실행 체크리스트와 나눕니다. 일부 캡처·미확인 붙임에서 전체 업무가 없다고 단정하지 않습니다. 날짜·조건의 문맥 연결은 여전히 교사 검수가 필요합니다.

오전·오후 시간은 유지하고, `15일~16일` 같은 축약 기간은 끝을 잘라내지 않고 전체 표기와 검수 사유를 남깁니다. 카드에 연결되지 않은 날짜는 `원문 미연결 참고 일정`에만 표시하며 확정 업무나 내 할 일로 만들지 않습니다. 교사가 수정·삭제한 날짜는 검증된 원문 위치로 구분해 다시 끌어오지 않으며, 다른 행사 셀의 같은 날짜는 별도로 남깁니다. 학부모·교직원 안내에는 이 미연결 일정을 넣지 않습니다.

### 문맥·근거 검토 (2026-09-17)

AI는 원문 줄·표 셀 번호를 선택하고 앱이 해당 내용을 그대로 인용합니다. 업무 행동과 담당·기한·제출물·제출처는 서로 다른 위치의 근거를 연결할 수 있습니다. 학교 업무와 외부 기관 업무·참고 일정을 구분해 표시합니다. 이 분류와 문맥 연결은 AI 판단이므로 사람이 최종 확인해야 합니다.

카드의 `근거`는 분석 당시 원문 버전과 실제 발췌를 보여줍니다. 선택한 줄·셀 위치를 저장하고 원문과 다시 대조합니다. 없는 인용·추측 페이지는 근거로 인정하지 않고, 인용이 여러 위치에 있는데 선택 위치를 검증하지 못하면 임의의 한 곳을 정확한 위치처럼 강조하지 않습니다. 원문이 바뀌면 이전 근거임을 표시합니다. 교사 수정값을 원문에 있던 내용처럼 표시하지 않습니다. 미검증 사실·상충 날짜는 카드에서 확인하며 정상 체크리스트와 구분합니다. 연도 미기재만으로 모든 실행 항목을 막지는 않습니다.

검증 실패 또는 확인 필요 항목이 있으면 같은 nano로 **최대 8개 항목을 1회 추가 재검토**합니다. 이미 분석한 원문을 다시 전송하며 추가 비용·시간이 발생합니다(추가 요청 30초 타임아웃, 자동 재시도 없음). 실패하면 1차 결과와 안내를 남기고 해당 실패 결과는 캐시하지 않습니다. 정상 항목은 다시 생성하지 않습니다.

문맥 검토를 위해 내부 분석 추론 설정을 `minimal`에서 `low`로 조정했습니다. 최초 분석이 이전보다 느릴 수 있으며 같은 원문의 캐시는 재사용합니다. 과거 경고가 많은 분석 캐시는 버전을 변경해 재사용하지 않습니다. 기존 원문이 정확하다면 앱 재시작 후 재분석만 하면 됩니다. 원문 자체가 잘못 읽혔다면 먼저 수정하거나 재OCR하세요.

카드에서 `내 할 일에 담기`를 누르면 업무 ID로 연결됩니다. 이후 카드의 날짜·담당·메모 수정도 내 할 일에 반영되고 완료 상태는 그대로입니다. 중복 담기·복사는 완료 처리하지 않습니다. 구버전의 텍스트 할 일은 원래 값과 완료 상태를 유지하며 자동 대응시키지 않습니다. 카드 없는 예전 실행안의 담기에는 기존 원문 연결 검사가 유지됩니다.

`업무로 저장` 후에는 편집 내용이 700ms 자동 저장됩니다. 업무 검색·진행중/완료 필터·재열기·부분 복사를 지원합니다. 처리 도중 편집하거나 업무를 이동하면 늦게 도착한 AI 결과가 편집 내용을 덮어쓰지 않도록 보호합니다.

분석 캐시는 원문·모델·검증 버전으로 구분하며 내부 분석은 완성된 행동부터 미리 보여줍니다. 앱의 안내문은 이제 현재 카드의 결정적 양식을 사용합니다. 학부모 초안은 학생·학부모 대상 행사와 참여 행동만 골라 내부 보고를 제외하며, 공개할 근거가 부족하면 발송 전 확인을 안내합니다. `원문 요약`은 마지막 분석의 원문 요약을 재사용하고, 원문 변경 후에는 재분석이 필요함을 표시합니다.

초안에는 원문·업무 버전과 생성 당시 확인 상태를 연결합니다. 내용뿐 아니라 확인 체크가 바뀌어도 기존 초안은 자동 덮어쓰지 않고 `이전 정보 기반`을 표시합니다. 새 초안을 만들면 직접 편집한 기존 안내문도 이력에 보존되며 `초안 이력`에서 이전 내용을 열람·복사할 수 있습니다. 처리 도중 편집한 경우 늦은 응답은 이력으로만 구분해 남기고 편집 화면을 바꾸지 않습니다. 카드 저장 성공 후 업무 보관함에도 저장하여 재열기가 가능합니다. 저장소 업그레이드 전 SQLite 백업을 만들며, 확인 상태 기록이 없는 구버전 초안은 본문을 보존하고 재확인이 필요한 것으로 표시합니다.

저장 도중 종료된 뒤 다시 열면 저장된 본문과 실제로 일치하는 초안 이력만 연결합니다. 대응이 없거나 여러 버전 중 확정할 수 없으면 `카드 버전 미확인`으로 표시하고 본문을 유지합니다. 별도로 저장된 새 초안은 이력에서 확인할 수 있습니다. 아직 저장하지 않은 입력의 복원이나 실제 정전·디스크 손상까지 보장하는 기능은 아닙니다.

`실행안으로 업무 도식화 만들기`는 검수한 결과로 별도 이미지 생성을 요청합니다. 현재 코드의 기본 모델 식별자는 `gpt-image-2.5-flare`이며 API 계정 접근 권한에 따라 실행 가능 여부가 달라집니다. 비용 안내 후 생성하고 PNG로 저장할 수 있습니다. 이미지의 한글·날짜·화살표 관계도 검수하세요.

창은 컴팩트 모드, 항상 위, 투명도 조절을 지원하고 설정을 다음 실행에 복원합니다. 업무 카드는 좁은 창에서 목록/편집을 위아래로 배치하며 하단 저장·충돌 해결·편집 취소 버튼은 고정하고 필드 영역을 스크롤합니다.

| `personal_todos.sqlite3` | 내 할 일·완료 상태·담을 당시 원문·분석 연결 정보 |
| `analysis_cache.sqlite3` | 분석 재사용 캐시 |
| `work_cards.sqlite3` | 문서·업무 ID, 원문 버전, AI 제안·교사 수정·확인·근거, 초안 이력 |
| `workspace_state.sqlite3` | 원문 지문, 현재 초안 연결, 승인 범위 연결 |
| `transfer_policies.sqlite3` | 가린 사본 정책·제외 문자열 지문·이미지 가림 좌표 |
| `settings.json` | 창 설정 |

첨부 문서는 앱 데이터 폴더로 복사하지 않고 원래 경로를 기록합니다. 업무를 삭제해도 캡처함 원본·외부 첨부·별도 내 할 일·분석 캐시·카드/초안 이력은 자동 삭제되지 않습니다. 기존 내 할 일 DB는 연결 테이블 추가 전 SQLite 백업(`*.before-work-cards-*.bak`)을 만듭니다. 기존 업무 DB는 구조를 바꾸지 않습니다. 다른 PC에서 이어 쓸 때 GitHub 코드만 가져와서는 API 키나 로컬 업무 데이터가 복원되지 않습니다.

로컬 보관과 외부 전송 없음은 다릅니다. 이미지/문서 OCR·업무 분석·도식화 요청 시 선택한 입력이 OpenAI에 전송되고 비용이 발생합니다. TXT/HWPX 읽기 자체는 로컬입니다. 전송 선택 화면과 상태 표시에서 실제 전송 종류를 확인하세요. 일반 업무 연락처만으로 반복 확인을 강제하지 않으며 로컬 패턴은 일부 의심 후보만 안내합니다. 이미지·API 파일의 개인정보를 전송 전에 자동 확인하지 못한다는 한계도 표시합니다.

`가리고 분석`은 텍스트 치환 사본, 또는 불투명 영역을 실제 픽셀에 합성한 새 RGB PNG만 전송합니다. 원본은 유지합니다. PDF/Office 원본 가림은 제공하지 않으며 필요한 텍스트를 붙여넣거나 페이지 이미지를 선택한 별도 사본으로 전환합니다. 원본 파일·숨은 레이어를 가린 파일이라고 전송하지 않습니다. 준비 실패·취소 시 원본 자동 대체가 없습니다.

가림 정책은 재열기·재분석·재OCR에 유지됩니다. 같은 이미지의 가림 좌표를 복원하고 원본이 달라지면 다시 선택합니다. 가린 원문의 편집 내용이 달라지면 기존에 있던 낱말만 사용했더라도 사본을 다시 선택합니다. 추가 가림은 기존 제외값을 유지하고, 이전 가림 해제·새 내용 추가는 범위 확대를 별도로 확인합니다. 가림을 넓히거나 해제하는 최종 책임은 사용자에게 있으며 학교의 외부 AI·개인정보 기준을 먼저 확인하세요.

Responses OCR·분석·재검토는 `store=False`를 명시합니다. 이것이 악용 모니터링 등 모든 서버 보관의 부재를 보장하지는 않습니다. 보관 설정과 학습 이용은 별개이며 실제 계정·API 정책을 확인해야 합니다. [OpenAI 데이터 제어 공식 문서](https://developers.openai.com/api/docs/guides/your-data)

학부모 초안의 일부 내부 업무 문장과 휴대전화·이메일·식별번호 형태를 걸러내지만 모든 개인정보를 제거하는 기능은 아닙니다. 이 필터는 생성 결과에 적용되며 API 전송 전 비식별화가 아닙니다. 자동 발송하지 않습니다. API 키·실물 공문·업무 DB는 저장소에 올리지 마세요.

## 검증과 업데이트 적용

2026-09-17 V2 1차 작업은 합성·mock 회귀와 Windows Tk 저장·재열기 검증을 수행했습니다. 이번에는 실제 공문·유료 API를 사용하지 않았습니다. 최종 시험 수, 초기 실패와 보완, 미검증 범위는 [VALIDATION.md](VALIDATION.md)에 구분합니다. mock 통과는 실제 모델 해석 정확도의 보증이 아닙니다.

```powershell
.\.venv\Scripts\python.exe -m unittest discover -s tests -q
.\.venv\Scripts\python.exe -m pip check
.\.venv\Scripts\python.exe tools/verify_release.py
.\.venv\Scripts\python.exe tools/verify_v2_release.py
```

`verify_v2_release.py`는 외부 소켓 통신을 차단하고 합성/mock 입력으로 카드·날짜·가림·저장·Tk 흐름을 검증합니다. 테스트 실패·건너뜀·통신 시도가 있으면 실패로 판정합니다. 유료 호출 옵션은 없으며 실제 모델 정확도나 실행 파일 배포 검증을 대신하지 않습니다.

`tools/verify_release.py --live`는 합성 문서로 기본 유료 API 3회, 내부 분석 재검토 시 최대 4회 호출합니다.
`tools/verify_date_tables.py "테스트.hwpx"`는 로컬 파일만 검사합니다. 여기에 `--live`를 붙이면 별도 합성 표로 유료 API 2~3회를 호출하며 해당 HWPX는 전송하지 않습니다.
`tools/verify_context_review.py --live`는 합성 공문 2건과 잘못된 기한 복구를 실제 API 3~5회로 시험합니다. `--case 1`, `--case 2`, `--case repair`로 개별 실행할 수 있습니다.
`tools/benchmark_ocr.py`는 로컬 OCR 비교 도구이고 `--cloud` 옵션은 유료 API를 사용합니다.

V2를 적용하려면 앱을 재시작하고 기존 업무에서 `AI로 업무 추출 / 재분석`으로 카드를 만드세요. 원문이 정확하면 재OCR은 필요 없습니다. 구버전 텍스트 기록은 자동 변환·덮어쓰기하지 않으며 새 카드로 연결한 내 할 일만 현재 수정값을 사용합니다.
