# Ssokly

만든 사람: docsusil

**Ssokly**는 학교 공문, PDF, 한글 문서, 웹페이지처럼 화면에 보이는 문서 일부를 드래그로 캡처한 뒤, **GPT-5 nano 기반 이미지 OCR**로 글자를 읽고, 교사가 실제로 해야 할 일을 순서와 일정 중심으로 정리해주는 데스크톱 MVP 앱입니다.

부제: **Pull tasks out of documents.**
설명: **드래그한 공문을 해야 할 일로 바꿔요.**

## 핵심 기획

공문 업무에서 중요한 것은 단순히 글자를 많이 읽는 것이 아니라, **잘못 읽지 않는 것**입니다. 그래서 Ssokly는 로컬 Tesseract OCR 대신 OpenAI의 이미지 이해 모델을 OCR의 중심에 둡니다.

```text
화면 영역 드래그 -> 캡처 원본 영구 보관 -> 장별 정밀 OCR -> OCR 텍스트 검수/수정 -> 업무 분석 -> 순서/루틴/일정/첨부 후속 실행 정리
```

현재 목표는 다음 한 가지 흐름을 정확하게 만드는 것입니다.

```text
공문 영역을 사각형으로 드래그하면 AI가 글자를 읽고, 인식된 텍스트가 앱의 텍스트 칸에 표시된다.
```

그 다음 단계에서 사용자가 OCR 텍스트를 확인하고 수정한 뒤 업무 분석을 실행합니다.

## 주요 기능

- 화면 영역을 사각형으로 드래그해서 캡처
- 캡처 이미지 또는 이미지 첨부 파일을 GPT-5 nano로 직접 OCR
- PDF, DOC/DOCX, RTF, ODT, PPT/PPTX, XLS/XLSX 첨부 문서 읽기
- 텍스트, Markdown, CSV, TSV, HWPX 첨부 파일을 원문 검수 칸으로 불러오기
- 캡처 이미지를 로컬 캡처 보관함에 원본 픽셀 그대로 영구 보관
- 캡처별 AI OCR 원문·교사 검수 최종본·상태·업무 연결을 저장하고 앱 재시작 후 즉시 복원
- 원본 이미지와 AI OCR을 나란히 보며 이름·연락처·날짜·표를 캡처별로 검수
- 검수본의 공백·탭·줄바꿈과 실제 업무 문맥을 익명화·정규화 없이 로컬에 그대로 보존
- 미분류/업무 연결/전체/휴지통 필터, 캡처 검색, 썸네일·OCR 첫 줄 미리보기
- 여러 캡처를 시간순으로 묶거나 현재 업무에 추가하고 장별 원본 유지
- 연결된 캡처 삭제 차단, 미분류 캡처의 복구 가능한 휴지통 정리
- 4K 캡처를 축소하지 않는 `high` 정밀 OCR과 원문 줄바꿈 보존
- 표는 행별 줄바꿈·셀별 탭으로 전사하고 원문에 없는 Markdown 표를 만들지 않음
- 재인식 결과 비교 후 적용, OCR 실패 시 직전 성공 원문 보존
- OCR 텍스트 직접 입력 및 수정
- 검수된 텍스트를 바탕으로 공문 업무 분석
- 원문 검수 후 `일정 확인표`, `업무 프로세스`, `활용 안내 양식`, `통합 실행안` 중 필요한 결과 선택
- Markdown 형식의 업무 순서, 반복 루틴, 일정 메모, 첨부파일별 후속 실행, 체크리스트 생성
- 전체 실행안 또는 일정, 체크리스트, 전달문, 첨부 후속 실행만 선택 복사
- 원문과 실행안을 로컬 업무 보관함에 저장하고 API 재호출 없이 다시 열기
- 업무 제목 검색, 진행중/완료 필터, 완료 전환, 안전한 삭제
- 저장된 업무의 편집 내용 700ms 자동 저장
- OpenAI SDK 지연 로딩과 빠른 무손실 PNG 처리
- OCR·문서 읽기·분석의 전용 진행 표시와 경과 시간 안내
- 큰 텍스트/HWPX 문서를 백그라운드에서 읽어 UI 멈춤 방지
- 핵심 작업면만 남기는 컴팩트 위젯 모드
- 항상 위 토글과 92~100% 투명도 조절

## 새 구조

```text
main.py
ui/app.py
  - 업무 보관함 사이드바와 원문 검수/업무 실행안 탭
  - 미저장 초안, 자동 저장, 비동기 작업과 편집 충돌 방지
  - 처리 종류·경과 시간을 보여주는 독립 진행 표시
  - 캡처 보관함에서 필터·다중 선택·묶기·재인식·복원

services/capture_service.py
  - 화면 전체 오버레이
  - 사각형 드래그 영역 캡처

services/capture_store.py
  - 캡처 이미지를 로컬 앱 데이터 폴더에 무손실 PNG로 영구 저장
  - SQLite에 AI OCR 원문과 교사 검수 최종본을 분리해 저장
  - 검수본을 검색·미리보기·업무 묶기에 우선 사용하고 재OCR에서도 보호
  - OCR 상태·업무 연결·휴지통 메타데이터 저장
  - 기존 임시 캡처는 삭제하지 않고 한 번만 안전하게 가져오기

services/task_store.py
  - SQLite에 업무 원문, 실행안, 상태, 출처 정보 저장
  - 캡처 원본은 앱 데이터 폴더에 영구 복사
  - 제목/원문/실행안 검색과 진행중/완료 필터

services/settings_store.py
  - 컴팩트 모드, 항상 위, 투명도를 로컬 JSON에 원자적으로 저장

services/ocr_service.py
  - PIL 이미지를 PNG data URL로 변환
  - OpenAI Responses API에 이미지 입력
  - OpenAI Responses API의 input_file로 PDF/DOC 계열 문서 전사
  - `high` 상세도로 원문을 교정·추측하지 않는 정밀 전사
  - 불확실한 글자는 `⟦불확실:…⟧`, 읽을 수 없는 부분은 `⟦판독불가⟧`로 표시

services/document_service.py
  - 첨부 파일 형식 분류
  - 텍스트 파일과 HWPX 본문 로컬 추출

services/ai_service.py
  - OCR로 얻은 텍스트를 순서, 루틴, 일정, 후속 실행 중심으로 분석

services/workflow_service.py
  - 결과에서 일정, 체크리스트, 전달문, 첨부 후속 실행 분리
```

## 설치 방법

Python 3.10 이상 사용을 권장합니다.

```bash
cd Ssokly
python -m venv .venv
.venv\Scripts\activate
pip install -r requirements.txt
```

`tkinter`는 일반적인 Python Windows 설치에 기본 포함되어 있습니다. 만약 tkinter 관련 오류가 난다면 Python 설치 옵션을 확인해 주세요.

## .env 설정 방법

`.env.example` 파일을 참고해 프로젝트 폴더에 `.env` 파일을 만듭니다.

```env
OPENAI_API_KEY=your_api_key_here
OPENAI_MODEL=gpt-5-nano
OPENAI_OCR_MODEL=gpt-5-nano
OPENAI_ANALYSIS_MODEL=gpt-5-nano
OPENAI_OCR_DETAIL=high
```

- `OPENAI_API_KEY`: OpenAI API 키입니다.
- `OPENAI_MODEL`: OCR/분석 모델을 따로 지정하지 않았을 때 쓰는 기본 모델입니다.
- `OPENAI_OCR_MODEL`: 이미지 OCR에 사용할 모델입니다.
- `OPENAI_ANALYSIS_MODEL`: OCR 후 업무 분석에 사용할 모델입니다.
- `OPENAI_OCR_DETAIL`: 이미지 OCR 상세도입니다. 기본값은 작은 글씨 판독을 우선하는 `high`입니다. 앱의 정밀 캡처 OCR도 `high`를 명시합니다.

API 키나 민감정보는 코드에 직접 적지 마세요.

## 실행 방법

가상환경 Python으로 실행하는 것을 권장합니다.

```bash
cd Ssokly
.venv\Scripts\python.exe main.py
```

창만 띄우고 콘솔을 쓰지 않으려면 다음처럼 실행할 수 있습니다.

```bash
.venv\Scripts\pythonw.exe main.py
```

그냥 `python main.py`로 실행하면 시스템 Python이 잡혀 필요한 패키지를 못 찾을 수 있습니다.

## 사용 방법

1. 앱을 실행합니다.
2. `화면 캡처` 버튼을 누릅니다.
3. 화면 위 공문 영역을 사각형으로 드래그합니다.
4. 캡처 이미지는 로컬 캡처 보관함에 원본 그대로 저장되고 OpenAI 정밀 OCR이 글자를 읽습니다.
5. `캡처함`에서 한 장을 선택하고 `원문 검수`를 눌러 원본 이미지와 AI OCR을 대조합니다.
6. 이름, 연락처, 날짜, 숫자, 표의 탭과 줄바꿈을 고쳐 `검수본 저장`을 누릅니다.
7. 원문 위의 `일정 확인표`, `업무 프로세스`, `활용 안내 양식`, `통합 실행안` 중 필요한 버튼을 누릅니다.
8. `업무로 저장`을 눌러 원문과 실행안을 로컬 업무 보관함에 보관합니다.
9. 저장 후 수정 내용은 자동 저장되며, 왼쪽 목록에서 검색·완료 처리·재열기할 수 있습니다.
10. 실행안에서 일정, 체크리스트, 전달문 또는 첨부 후속 실행만 따로 복사할 수 있습니다.

헤더의 `캡처함`을 열면 아직 업무에 넣지 않은 캡처, 업무에 연결된 캡처, 전체 캡처와 휴지통을 나눠 볼 수 있습니다. 한 장을 선택한 뒤 `원문 검수`를 누르면 AI OCR 원문과 교사 검수 최종본을 분리해 보존합니다. 검수본은 이후 검색, 미리보기, `새 업무로 묶기`, `현재 업무에 추가`에서 우선 사용됩니다. 현재 업무가 같은 캡처의 수정 전 OCR을 그대로 담고 있으면 검수 저장 즉시 안전하게 반영하고, 이미 교사가 편집한 업무라면 자동 변경하지 않고 비교 창을 엽니다. 재OCR은 최신 AI 원문만 갱신하며 교사 검수본을 덮어쓰지 않습니다.

캡처 목록은 최근 250개를 먼저 표시하며 제목 대신 캡처 출처와 저장된 OCR 전문을 검색할 수 있습니다. 여러 장 정밀 OCR은 이미지마다 API를 한 번씩 호출하므로 실행 전에 호출 횟수를 안내하고, 한 번에 최대 20장으로 제한합니다.

이미지, PDF, DOC/DOCX, RTF, ODT, PPT/PPTX, XLS/XLSX, TXT, Markdown, CSV, TSV, HWPX 첨부 파일은 `첨부 파일 열기`로 읽을 수 있습니다. 구형 HWP 파일은 한글에서 HWPX 또는 PDF로 저장한 뒤 열거나 필요한 영역을 캡처해 주세요.

창 위쪽의 `컴팩트`를 누르면 업무 보관함과 상세 동작을 접고 캡처·입력·분석·저장에 필요한 작업면만 남깁니다. 컴팩트 상태의 `전체 화면`으로 원래 창 크기와 구성을 복원할 수 있습니다. `항상 위`와 `투명도` 슬라이더는 컴팩트 모드와 독립적으로 사용할 수 있으며 다음 실행에도 유지됩니다. 창 테두리와 Windows 제목 표시줄은 모든 모드에서 유지됩니다.

## 로컬 데이터

- 업무 DB: `%LOCALAPPDATA%\Ssokly\ssokly.db`
- 캡처 원본: `%LOCALAPPDATA%\Ssokly\capture_inbox\*.png`
- 캡처 OCR·검수 DB: `%LOCALAPPDATA%\Ssokly\capture_inbox\capture_inbox.sqlite3`
- 창 설정: `%LOCALAPPDATA%\Ssokly\settings.json`
- 저장 업무의 캡처 사본: `%LOCALAPPDATA%\Ssokly\captures`
- 캡처 보관함 원본과 메타데이터: `%LOCALAPPDATA%\Ssokly\capture_inbox`
- 이전 버전의 Windows 임시 캡처는 최초 실행 시 비파괴 방식으로 캡처 보관함에 한 번 가져옵니다.
- 첨부 문서는 앱 데이터 폴더로 복사하지 않고 원래 파일 경로만 기록합니다.
- 업무를 삭제해도 캡처 보관함 원본과 외부 첨부 원본은 삭제되지 않습니다.

## 반응 속도와 처리 상태

- OpenAI SDK는 앱 시작 때 불러오지 않고 첫 OCR·분석 요청의 작업 스레드에서 불러옵니다.
- 캡처와 OCR 전송용 PNG는 픽셀 손실 없이 저장하며 일반적인 3840×2160 캡처를 축소하지 않습니다.
- TXT와 HWPX 파일 읽기, OpenAI OCR·문서 읽기·분석은 백그라운드에서 처리합니다.
- 처리 중에도 업무 검색·필터, 제목·원문·실행안 편집과 결과 복사를 사용할 수 있습니다.
- 처리 도중 원문이나 실행안을 수정하면 늦게 도착한 AI 결과를 적용하지 않아 사용자 편집을 보호합니다.
- 여러 캡처는 합친 이미지로 읽지 않고 각 원본을 따로 OCR한 뒤 저장된 전문만 시간순으로 묶습니다.
- 재인식 실패는 이전에 성공한 OCR 전문을 지우지 않습니다.
- 처리 중인 여러 장 OCR을 취소하고 다른 업무로 이동하면 현재 요청 뒤의 남은 API 호출은 시작하지 않습니다.
- OpenAI 요청은 요청당 120초 타임아웃과 최대 1회 재시도를 사용합니다.

## 정확도 원칙

- OCR 결과는 사용자가 원문과 대조해 검수하는 것을 전제로 합니다.
- AI OCR 원문과 교사 검수 최종본은 서로 덮어쓰지 않고 함께 보존합니다.
- 검수본은 이름·연락처를 포함한 실제 업무 문맥, 앞뒤 공백, 탭과 줄바꿈을 그대로 저장합니다.
- 새 정밀 OCR 결과가 검수본과 달라도 검수본은 보호되고 `OCR 갱신` 상태로 표시됩니다.
- 같은 캡처를 여러 Ssokly 창에서 동시에 수정하면 오래된 검수 창의 저장을 거부해 최신 원문과 검수본을 보호합니다.
- 공문 분석은 OCR 텍스트가 정확할수록 좋아집니다.
- 표나 작은 글씨는 캡처 영역을 너무 좁게 잡지 말고, 글자가 선명하게 보이는 배율에서 캡처하는 것이 좋습니다.
- OCR은 맞춤법·띄어쓰기·숫자·기호를 임의로 교정하지 않고, 잘린 문장을 추측해 완성하지 않도록 지시합니다.
- `⟦불확실:…⟧` 또는 `⟦판독불가⟧`가 남은 원문을 분석하려 하면 먼저 검수를 안내합니다.
- 날짜, 숫자, 대상, 제출 방법과 첨부파일명은 반드시 원본 이미지로 최종 확인해 주세요.

## 개인정보 및 보안 주의

Ssokly는 이름·연락처 등 실제 업무 내용을 자동으로 익명화하거나 변경하지 않습니다. 캡처 원본, AI OCR 원문과 교사 검수본은 이 PC의 로컬 앱 데이터 폴더에 원문 그대로 저장됩니다.

다만 `정밀 OCR`이나 `업무 분석`을 실행하면 사용자가 선택한 이미지 또는 텍스트가 OpenAI API로 전송될 수 있으므로, 실제 업무 사용 전 학교와 기관의 개인정보 처리 및 외부 AI 서비스 이용 지침을 확인해야 합니다. 로컬 저장과 외부 전송 없음은 같은 의미가 아닙니다.
